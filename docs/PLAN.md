# PLAN

Design lives in the wiki (stateless-agent-architecture.md); this file only sequences phases.

**Iron rule — effector never depends on Aura crates.** All coupling with Aura is
limited to the frame protocol (serde types in `effector-protocol`). The effector is
upstream-agnostic: any service that speaks the frames can drive it — the
"Aura Booth" deployment form is implemented entirely on the Aura side
(connection plane adapts outbound WS frames to Realm mailbox semantics);
scheduling semantics the effector needs (same-node seriality, call timeout) are
its own mailbox + deadline, not Aura's `pending_calls` — that scan is
control-plane side. Hitching to another service = that service holds the WS
server; effector code is unchanged.

## Milestone A — Runtime

- [x] Phase 0 — Workspace skeleton: `crates/{runtime,protocol,config}`; task contract (tool_call in → tool_result out); capability surface definition (fs scope, command exec, network — what a skill may touch; no credentials). Isolation model: **the Effector itself runs as a container** (base image + on-demand dependency install, e.g. Python + libs) — isolation is per-node, not per-skill. Consequence stated openly: skills inside one container share its filesystem; the "restricted world" is enforced by the capability surface (app-layer checks), not by container boundaries. Acceptable under user-namespace isolation (isolation cuts by user, not by skill); revisit per-skill isolation only if multi-tenant shared nodes become real.
- [x] Phase 1 — Runtime carriers: steel / python (PyO3) / wasmtime (the Wasm engine; wasmer/wasmi were engine candidates, not languages; koto/rune predate the three-language ruling and are dropped) + nushell (subprocess, CGI-shaped: JSON via stdin, structured result via stdout — completes the language-selection quadrant grid), feature-gated; per-operation language declaration; script-only operations end-to-end.

## Milestone B — Effector

- [~] Phase 3 — Outbound registration: deploy on any machine and it operates that machine. Connection-direction/data-direction decoupling: on startup the effector actively connects to the control plane and registers (presence + capability list), keeps the connection open, tasks are pushed down the connection (WS frames) — no inbound ports, network ingress topology irrelevant; no degraded fallback (long-polling explicitly rejected — WS-only is the contract). Effector is an Aura Booth type (booth_type = Effector, partition_key = node_id): the control plane's calls are standard `ctx.invoke()` routing — registration credential = user credential, capability list (the carried languages) written into the user's namespace registry; target resolution = user namespace + node alias + operation (`effector:home-pc:read_file`), where the operation is a registered booth/script — the Effector ships no built-in operations, every operation is user-written or AI-generated code delivered through a carrier (nushell/python/steel/wasmtime). Same-node seriality free via Booth mailbox semantics; timeout/error reuse `pending_calls` deadline scan.
  - DONE (2026-09-16): remote wrapper first cut — `remote.rs`: outbound WS (tokio-tungstenite), Register frame (node_alias + credential from env + carriers) → Registered handshake, task downlink loop (one Call per frame → resident session → Result frame), reconnect with exponential backoff; session key = `effector/<node_alias>/<session>` (`session` is the caller's opaque residency identity; `entry` names the point in the delivered code); binary entry (`main.rs`: config path arg, JSON config, credential from env); `Frame` transport envelope added to protocol. Acceptance: fake control plane over real TCP WS — register handshake + inline steel call + result round-trip.
  - ctx bridge over the wire (2026-09-16): `Frame::Host` bidirectional round trip (`HostCall{host_call_id, call_id, op}` / `HostResult`); HostOp = StateGet/Set/Delete + Invoke; the effector builds a real HostBridge whose fns send over the connection and block on the correlated reply (writer task + reader dispatch = full-duplex frames); the gateway resolves via pending_remote's instance (call_id → instance) — state scoped to the remote booth instance's own fields, invoke rides the unified call model (hot tier; cold/pending over the wire not yet). Acceptance: E2E script does ctx_state_set/get + ctx_invoke to a local booth, state lands on the remote instance's store fields.
  - Link payloads (2026-09-16): `CodePayload::Link` consumed — GET the content-hash URL (ureq, blocking inside the session task), verify sha256 before execution (mismatch = error value, never silent accept); zero cache honored (fetch only what the call declares, nothing held between calls). Acceptance: real HTTP endpoint + fake WS control plane — correct-hash fetch executes, wrong-hash rejects. WS chunked delivery for `link` (restricted networks) deferred until a real restricted-network deployment demands it.
  - Sandbox enforcement (2026-09-16, Phase 5): `SandboxPolicy` (None | Bubblewrap{allow_write, deny_read, cwd, allowed_domains}) threaded through `Sessions` — policy belongs to the DEPLOYMENT FORM (effector = unattended external code → wrap; aura in-process = user's own trust domain → None). NushellSession::spawn execs `bash -c <bwrap …>` when wrapped: the whole resident REPL lives inside the mount namespace (fs allow_write from CapabilitySurface.fs_scope, network unshared). Per-session file dir moves INSIDE the policy cwd when wrapped (/tmp is tmpfs — files vanish). `EffectorConfig.sandbox` (default true) + fail-closed check (sandbox=true without bwrap on PATH = startup panic). Verified: nu resident session inside bwrap — env state persists, network unreachable (`--unshare-net`), session files bind-mounted.
  - Declared, enforced (2026-10-14, effector ADR-0001): the jail is built from the node's own `CapabilitySurface` — `fs_scope` (write scope), `deny_read`, and `cwd` (undeclared = temp dir) now map field-for-field in `sandbox_policy_for`, and a declaration with no enforcement point is refused at startup (`EffectorConfig::validate`: `command_exec: true`, any non-`none` `network`). The rule: a field may be declared only once its enforcement point exists.
  - Remaining: domain allowlists (proxy filtering for `NetworkPolicy::Allow` — `validate` refuses the claim until this is wired); seccomp profile from sandbox-runtime; the mechanism for a `command_exec` grant (or that field's retirement); read-denial patterns (the runtime accepts patterns, the declaration passes strings); cold-call resolution over the wire.
  - OWED with prism Phase 1.8 step 2 (cross-repo; both ends land together, see `~/world/prism/docs/handshake-plan.md`): node identity at the CLI — `effector keygen [--out <file>]` (ed25519 pair, private key 0600, public key printed base64) and `effector register <config.json>` (one-shot handshake, print the verdict, exit), `identity_file` replacing `credential_env` (a key is a file, perms OS-managed; a shared secret in the environment is the thing being retired), and the protocol reshape in `effector-protocol` — `Challenge{nonce}` (host→effector) plus `Register{node_alias, public_key, signature, carriers}` with the signature over nonce+alias. Aura ADR-0015 owns the decision; the frame home is ruled (induction ADR-0001 Consequences, 2026-10-13: `HostOp` and the pipe `HostFrame` are two transport encodings of one `Arm` vocabulary), so this is no longer blocked on a design question.
- [ ] Phase 4 — Operation dispatch: the Effector never sees a skill. A skill is emergent in the Krystallizer graph; Gravity drives the LLM — the LLM selects the operation and generates its arguments, and that selection is the skill's execution. What the Effector receives is an operation, its declared language, its code, and its arguments. Two payload forms declared in the task context: `inline` (bytes in the frame — py/steel, KB-scale) and `link` (URL + content-hash version + expected hash — Wasm, MB-scale; optional control-plane HTTP port, CDN-cacheable by version, hash verifies bytes). Restricted networks (WS-only egress): `link` degrades to chunked delivery over the same WS channel — the control plane decides at frame assembly; the Effector consumes whichever form is declared. Zero cache: Gravity resolves against Krystallizer live on every tool call; the Effector holds nothing between calls and initiates no fetch of its own.
- [x] Phase 4.5 — Host-side storage service (ADR-0010): **WITHDRAWN (2026-09-20)**.
  - Landed, then removed in full: `kv_executor.rs` (NestStorage receiver role), the `Frame::Kv` / `KvFrame` / `Frame::KvRefused` wire frames, `KvExecutorDecl` + `EffectorConfig.kv_executors` (`name` / `ns` / `data_dir`), the `KvRegistry` dispatch arm, both KV test files, and the effector's `okm-core` / `okm-wire` dependencies — the effector now has no okm coupling of any kind.
  - Structural reason: **the effector holds no storage.** Data has no reason to live on an execution node — hosting it adds a directory to place, size and back up, plus an engine lifecycle, while every operation the node runs is delivered per call and holds nothing between calls. The key prefix is not an execution-node concept either: it is what the CONTROL PLANE derives from the sender's identity and business logic (Gravity's data = its own ns, then the partition id, then the event id, resolved by lookup), so a declared prefix on a dumb receiver could only restate a decision taken elsewhere — and a `ns`-shaped field carried okm's vocabulary into a component whose contract is bytes only.
  - Consistent with okm ADR-0010, which places the receiver on Aura ("Aura's remote-storage receiver", "Krystallizer hosting on Aura"): the effector's executor was a second placement of the same role, not a fifth backend shape.
  - **Where the persistence requirement is served instead — the founding path, not a fallback**: a delivered script's durable state goes through the ctx bridge (`ctx_state_get` / `ctx_state_set` / `ctx_state_delete` / `ctx_invoke` ride `Frame::Host` to the control plane, which executes them against its own store). This is the project's opening stance ("持久化与恢复全部沉到记忆系统"; stateless = the executor holds no session state, state lives in Krystallizer), so persisting from a script is the initial requirement and the effector holding nothing between calls is what serves it — never describe it as a someday case.
  - **And the effector must not hold the data plane's credentials**: the node runs untrusted code in a container, so it is not given storage credentials ("容器（执行不受信任代码）不持有数据面凭证"). Hosting an engine there contradicts that stance, not merely adds an operations burden — this is the hardest of the reasons.
  - Anti-pattern recorded so it is not re-proposed: an operation that genuinely needs local temporary data creates its own SQLite file via python/nushell. That is an operation's private business, never a effector-side storage surface.
- [ ] Phase 5 — Scope constraints: fs scope, command exec, network declared per-effector registration and enforced on delivered scripts at execution. Whether an operation is AI-generated-live or pre-audited is control-plane policy (Gravity/Krystallizer), not a Effector concern. This is the ONLY containment layer (no per-operation container boundary beneath it) — the check must be enforced at execution, not just at dispatch-declaration. LANDED 2026-10-14 (effector ADR-0001): the declaration surface is completed for what the jail CAN enforce — `deny_read` and `cwd` became declarable and `fs_scope` is now documented (and treated) as the WRITE scope — and every unenforceable claim fails the startup instead of being published, so a declared field must name its enforcement point.
- [ ] Phase 6 — Data-path discipline: control plane carries instructions and result summaries only — Result stays message-sized; large artifacts (files, binaries) are handled by the operation on the Effector side (local fs, user-configured transfer tooling, transport operations). Transport-reachability requirements (direct connection / same VPN) ride skill metadata on the Gravity side — the control plane neither knows nor governs the data path. AI-generated invoke arguments are instruction semantics (paths, options, fragments) and naturally bounded; a loose inbound message cap on the control plane guards anomalies only, it is not a data-plane design.

Loose ends:

- RESOLVED 2026-10-14 (effector ADR-0001, `cefde68`): `EffectorConfig.sandbox` is read — `false` passes `SandboxPolicy::None`, `true` builds the jail from the node's own `CapabilitySurface` (`remote.rs`, "the field IS the switch"). The bwrap-presence check the old note named has no call site in this tree; the fail-closed gate that runs is `EffectorConfig::validate`, called at the top of `remote::run`.

Deferred gates:

- Aura-embedded form (Wasmtime-heavy-isolation sibling): deferred until the remote effector is stable; embedding changes nothing in the task contract.
- Skill packaging/install lifecycle: skills are emergent (Krystallizer graph), not installed artifacts — revisit only if cold-start cost of spec fetch becomes measurable.
