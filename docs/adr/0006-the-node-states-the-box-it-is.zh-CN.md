# 0006 — 节点说明它是哪台机器，而对其用途一字不提

状态：已采纳（2026-11-20）

## 背景

`Register` 带的是 alias、carriers 和 class。alias 是**连接**对外的名字：任何用这个名字拨号的人都能把它夺走（ADR-0015 §7 的顶替纪律），它由部署选，并随进程一起消失。于是"同一个节点"实际含义是"最近一次以 `x` 拨号的那个东西"，而线上协议无法回答这件事留下的两个问题：

- 一台重启后换了 alias 的机器，看起来就是另一台机器。控制面关于它学过的一切 —— 位置、历史、一份 grant —— 都属于一个不再存在的名字。
- 两台机器抢同一个 alias，只会表现为一次顶替，而永远不会表现为"哪台硬件"。

而标签填不了这个缺口：ADR-0005 §2b 已定，一个能说出自己标签的节点也就能说出别人的。于是注册帧里关于硬件的东西一个字都没有。

问题因此是：在不能说"它用来干什么"的前提下，节点可以说自己什么？

## 决定

1. **`Frame::Register` 增加 `machine`：一个不透明字符串，命名这台机器。** 它不是凭据、不是授权、也不构成对任何特权的声索 —— 它只是关于进程所跑硬件的一句陈述。空值表示"未识别"，那是一个事实而不是错误。

2. **节点按顺序从第一个能回答的来源取值：**
   1. `capabilities.machine` —— 部署的说法。它优先，因为管着十二台节点的操作者才知道哪台机器是哪个，而容器的 `/sys` 要么是宿主机的、要么什么都没有。
   2. 硬件自己的序列号：先是 SMBIOS UUID，再是产品序列号，再是主板序列号，再是设备树的 `serial-number`。容器通常看得见宿主机的 DMI，这恰好就是"这是哪台机器"所需的答案。
   3. **只生成一次并保存**在节点状态目录里的 id（`$EFFECTOR_STATE_DIR`，否则 `$XDG_STATE_HOME/effector`，否则 `~/.local/state/effector`）。这是 VM、藏了 `/sys` 的 jail、没有 DMI 的 SBC 的情况：没有序列号可读，而一个什么都不报的节点，每重连一次就重启自己的历史。`create_new` 让这次写入抗竞争：同一台机器上同时启动的两个节点，一个写成功，另一个读到赢家的 id。
   4. 都拿不到 → 空（未识别）。

3. **让自报成立的是唯一性，不是无害性。** 这里区分的不是"含不含特权"，而是**一个错的声明能否与对的区分开**。

   机器标识按构造就是唯一的：它属于一台机器，没人猜得到，而两个节点报同一个值就是一个矛盾 —— 抄来的序列号，或者一台撒了谎的机器，控制面说得出这一点（aura 以 `same_machine` 报出）。**那条报告本身就是让这个值可以自报的那道校验。**

   标签在每一个轴上都是反的。`site:home` 是一个小而可猜、公开有意义的字符串；**很多**机器本来就合法地是 `site:home`，所以错的声明与对的声明无害地撞在一起，没有任何东西与它矛盾。标识猜不到，也不可能被共享而不出问题；标签既可猜，又天生被共享。

4. **标签方面什么都不变。** 它们仍然是准入方的说法（ADR-0005 §2b），由准入时从 grant 签发，交给持有该连接的那一方。

## 否决的方案

- **从 `/etc/machine-id` 派生身份。** 那是**操作系统安装**的身份：重装即重置，于是一台重装过的机器会悄悄变成一台新机器，而它的序列号没变。借用它，等于把节点的身份挂在别人的生命周期上。
- **对 alias 取哈希当机器身份。** 它是从那个定义上就不稳定的东西派生的；改个名就分叉出第二台机器。
- **没有状态目录时在内存里生成一个 id。** 每次启动都变的 id 比空值更糟：空值说"未识别"，控制面可以据此决定；而每次都是全新的 id，看起来像是无穷多台新机器。
- **把 machine 并进 alias。** 那会把"连接对外答的名字"和"它跑在哪台机器上"焊在一起，于是机器永远改不了名、名字也永远搬不了家 —— 而顶替规则（ADR-0015 §7）正是因为这两件事不是一件事才存在。

## 后果

- **一台机器可以跨重连、跨改名被认出来**，这才让 grant、位置或操作者的历史能挂在硬件上，而不是挂在一个进程自己挑的名字上。
- **控制面把两个事实分开存**：路由用的 alias，关联用的 machine。两条连接报同一台机器会被报出来 —— 同一台机器换了名字，或者两个节点都在声称同一个序列号 —— 而没有任何东西替人裁决哪种读法是对的。
- **未识别的节点不等于另一个未识别的节点。** 空永不等于空：两台说不出自己是谁的机器，不能被一个过滤器混成一台。
- **没有任何东西拿 machine id 做认证。** 如果将来要把 grant 绑到序列号上，验证必须来自准入（注册表），而不是来自这个字段。

## 测试

- `crates/runtime/src/remote.rs` 的 `machine_tests` —— id 只生成一次、写进状态目录并原样读回；磁盘上已有的文件绝不被覆盖；部署声明的值优先，空值会顺着链条往下走而不 panic。
- `crates/runtime/tests/remote.rs` —— 节点的注册帧携带部署声明的 `machine`，按控制面收到的样子断言。
- aura `crates/realm/src/pool.rs` —— 同一台机器出现在两个 alias 下会被报出来而不是合并；`by_machine` 对真实序列号给出答案，对 `""` 拒绝作答。
