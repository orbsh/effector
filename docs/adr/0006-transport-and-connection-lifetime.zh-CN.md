# 0006 — 传输与连接生命周期：先本地套接字，UDP 要有数字支撑

> **语言：** [English](0006-transport-and-connection-lifetime.md)（主） · [中文](0006-transport-and-connection-lifetime.zh-CN.md)

**状态：** 已接受（2026-11-19）。它裁决用什么承载帧、由谁结束连接；不改变任何已经存在的载体。
**日期：** 2026-11-19

## 背景

ADR-0004 把载体变成接口。本记录说清有哪些实现、按什么次序重要，以及最容易搞错的那一半 —— 什么结束一条连接。

两个事实是在开发机上量出来的，不是假定的（256 B 往返，2 万次，Python 绑定所以绝对值偏高、比值有意义）：

| 载体 | 往返 |
|---|---|
| 管道（今天的 `exec`） | 0.89 µs |
| unix socket | 0.81 µs |
| TCP loopback | 4.00 µs |

管道与 unix socket 是同一个量级；loopback TCP 差五倍，但比"人开始察觉"低两个数量级。所以真正的问题不是"怎么比管道更快"，而是"两端不在一台机器上时怎么办"——那时代价是网络的往返，不是系统调用。

## 决定

**裁决 —— 载体的选择跟随位置，不跟随偏好：同机用 unix socket；跨机用 TCP，直到某个测量说不行；数据报只在数字要求它时才上。**

1. **同机：unix socket（`uds`）。** 与管道同价，能活得比拉起它的父进程更久（常驻摊位要的正是这个），不需要握手、不需要为 TLS 辩论，而且对端身份由内核背书（套接字文件的权限）。管道保留：每轮一进程的子进程确实想随父而死，EOF 是最干净的停止信号。

2. **跨机：TCP，不是 UDP。** UI 帧是人眼速率的快照；TCP 多出来的毫秒不可见，而数据报带来的失败模式（乱序、丢包、自己实现的重传策略）会以 bug 的形式可见。慢启动不是听起来那么大的问题：每条连接只付几次往返，而连接是刻意长命的。

3. **数据报只在有测量要求时上，绝不为满足某种原则。** 如果流式 token 或高频输入真的暴露出跨用户的队头阻塞，答案是 KCP（可靠 UDP，可调重传，无 TLS）或 QUIC（自签内部 CA —— QUIC 强制 TLS 1.3，但"强制 TLS"不等于"强制公网证书"）。WebTransport 的 TLS 要求是**浏览器**的约束：进程对进程不是浏览器，内部明文数据报是正当的。

4. **每用户一条连接；协议不携带丢弃策略。** 隔离就是让慢消费者无害的那件事 —— 他只堵住自己那条连接。优先级、合并、"哪些操作可丢"不是传输的事，本记录把它们排除在外，而不是留给以后加。

5. **单帧有上限（16–32 KB）。** 唯一保留的几何规则：无上界的帧会让它自己那条连接阻塞整整一个发送时长，而这是帧的性质，不是调度策略。

6. **生命周期归载体，而且已经在配置里陈述过了。** `LeaseConfig { idle_secs, max_idle_secs, exit_on_disconnect }`：容器节点没活干就走、随容器结束（没有池管理器、没有回收器）；宿主节点永不过期，改为重连。管道载体随 EOF 结束。没有别的东西决定这件事。

7. **进程之间不要求 TLS。** 有一端是浏览器（WebSocket、WebTransport）时才要求，因为那是浏览器唯一提供的通道。effector 与 realm 之间，连接由控制面铸造的 token 授权（ADR-0003），套接字是本地或可信网络；在那里加 TLS，是用一个没人要的内部 PKI 去防一个部署本身已经排除的威胁。

## 后果

- **常驻摊位是一个 socket 部署。** "一个 booth、所有分区、一个 effector 实例"之所以可表达，正因为载体是有租约的套接字，而不是继承管道的子进程。
- **宿主/容器之分仍是节点的性质，不是调用的性质。** 节点说它是什么（`Register { class }`），调用方说它需要什么（`requires`），不匹配就按名字拒绝，不降级。
- **重连是宿主节点的一等状态。** `exit_on_disconnect: false` 意味着节点会回来并重新注册；因此选点要按标签而不是按套接字寻址，否则回来的节点就够不到。
- **不会写池管理器。** 容器就是生命周期；回收器会成为"节点该何时死"的第二个、会打架的事实来源。
- **是测量打开数据报的门，不是论证。** KCP 或 QUIC 落地时，本记录补上那个支撑它的数字。
