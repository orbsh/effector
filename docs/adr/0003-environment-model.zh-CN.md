# 0003 — 边界是环境；能力面表达意图，不承担安全

> **Languages:** [English](0003-environment-model.md) (primary) · [中文](0003-environment-model.zh-CN.md)

**Status:** Accepted (2026-11-16)。本记录推翻两条旧记录：PLAN Phase 0 的「隔离是 per-node，能力面构成那个受限世界」，以及 Phase 5 的「能力面是唯一容纳层，底下没有按操作的容器」。
**Date:** 2026-11-16

## Context

ADR-0001 把整套容纳叙事建在「一次调用一个 jail」上：bubblewrap 包住一个子进程，每一项声明出来的能力都落到这个 jail 的某个字段（`fs_scope` → 写范围，`deny_read` → 读屏蔽，`cwd`，`network` → 代理允许清单）。当时选每次都起 jail 的理由是容器太慢；由此推出的结论是：能力面就是安全边界——下发的代码与节点共用同一个用户、同一份文件系统视图、同一棵进程树，所以模型可能采取的每一个操作都必须事先点名并在执行时检查。

这两半理由现在都不成立了。

**成本这一半消失了。** 本机实测，对着热的本地镜像：`docker run --rm <image> true` 0.18–0.21 s，换成 `python3 -c pass` 0.16–0.23 s，同一个容器里连起两次解释器也还是 0.17 s。解释器在噪声里，价格全在建容器上。某个容器运行时宣传的 2.5 ms 不是这里该看的数字；该看的是：一次调用一个容器的代价与当年一次进程派生相当，而按任务留存的容器每个任务只付一次，不是每次调用付一次。当年慢的是桌面 VM 和冷拉镜像，不是 API。

**安全这一半是错的，而且失败在人这一侧，不在技术一侧。** 逐操作审批受限于注意力，而注意力不可扩展：一个人连着读四十个权限请求之后就不再读了；一条自动化的流程卡在一个拿不到的审批上，比直接失败更糟。基于审计的模型于是不得不为「本来就可以重建」的事情申请许可——重生成一个构建产物、删掉一棵临时目录——这在表面上就荒谬，更糟的是它把审批人训练成不看就点同意。这与 gravity + aura 存在的理由直接相悖：一个用来并行跑很多轮的架构，不能把并发挤进一个人的审批队列。

**真正能扩展的是把资源绑到环境上，而不是把操作绑到许可上。** 一个你能读的仓库就是一个你可以随便用的资源，因为损害被「你还能碰到什么」限住，而且 `git` 可以撤销。持久化只有两种手段覆盖得住：**git 承载文本与代码**（版本、回滚、合并），**对象存储承载声明过的产物**（训练好的模型、数据集、构建输出）。容器里 `rm -rf /` 的代价只是当前这个任务，恢复方式就是把任务再跑一遍。本记录采用这个模型，并因此撤掉能力面的安全身份：节点声明的，从此是它**打算做什么**、什么可以被审计，而不是「不受信任的代码与宿主之间隔着什么」。

## Decision

**裁决——执行环境是边界，且边界按任务选定。**

1. **`Environment` 取代 `SandboxPolicy`，而选择有两根轴：这段代码属于谁，以及由什么来跑。** 第一根轴是信任域，它决定安全叙事；第二根轴是后端，它决定可用性。
   - **进程内** —— 代码属于引擎自己的域：aura 的 realm 脚本（按摊位住留，realm Phase 2.6），以及 aura 自己执行的操作。后端：在节点自己的地址空间里直接调用（`steel`、`python`）。这里不声称任何边界，因为没有不受信任的东西需要被围住——这是实话，不是漏洞。
   - **宿主** —— 代码属于机器所有者的域，且需要只有机器才有的东西（组合一份系统配置、读取指定文件）。后端：宿主上的子进程，不起 jail；用一份小授权加审计，而不是拦截器。
   - **一次性** —— 代码不属于任何人：它是一刻之前一个模型在 turn 里刚写下的。本机后端：经 Docker Engine API 起的容器（`Container { image, network, task }`），宿主的东西一样都看不见，资源上限就是容器的上限，kill 句柄就是容器。集群后端（后续）：经 k8s API 起的 `Job`——**不是** pod 里跑 `docker run`，pod 里没有 daemon。
   两根轴刻意正交：没有 Docker 的机器失去一次性类的本机后端，保留另外两类；集群则把一次性类拿回来，而调用看起来毫无变化。任何后端都不许搬动一次调用的信任域：信任域由控制面对代码的来源域声明，所以一个 turn 刚写下的行不能因为"进程内更快"就被进程内执行。
2. **契约就三样东西，且不提「进程」。** 环境交出一个执行器：一个入口、一个承载 induction 帧的载体、一个能杀掉它的句柄。对进程或容器后端，载体是一对管道；对进程内后端，帧就是值——这就是为什么契约写在执行器上而不是管道上。「表现得像一个子进程」从来不是要求，那只是 jail 碰巧的实现方式。

   三档的留存叙事是同一个想法在三种时间尺度上，这不是巧合：realm 按摊位生命期留住它的常驻执行器（随摊位一起死），宿主节点在调用之间什么都不留，容器活过它所在任务的宽限期。环境的留存期等于它的作用域，作用域结束就是它的结束。
3. **容器按任务键控，键由控制面铸造。** `ToolCall` 今天不带任务身份（只有 `call_id`、`kind`、`stream`、`executor`、`entry`、`language`、`encoding`、`args`、`code`），而 `CodeRef` 里的 `memory_scope` 是错的替身：那是记忆面，跨任务存在，同一个节点上的两个用户会在里面撞上。缺 `task` 字段 = 每次调用一个新容器——这是安全默认，不是靠猜的兜底。
4. **不按环境规格键控。** 两个任务即使想要同一个镜像、同一组资源，仍然是两个任务；因为规格哈希相同就共用容器，等于把一个用户的残余暴露给另一个用户——那是一个长得像缓存命中的安全洞。同用户之间共享倒是安全的，但派不上用场：需要大规模并行的场景本该由集群承担，而另一台机器、集群里的容器本来就共享不了。
5. **不按资源集合键控。** 任务是跑着跑着才发现自己需要什么的。用资源派生键，就只能在「资源中途出现时重启容器」和「把任务声明冻结在开始时」之间二选一，两个都错。
6. **生命周期是空闲留存池，且退出时不保存任何东西。** 调用返回后容器留 15 s；同一个任务的新调用取消计时、执行、按上一轮的两倍重新计时（30、60、120、240，封顶 300 s）。封顶的理由：闲置几分钟之后，等它的成本已经高于冷启动，而一个能闲置这么久的任务对延迟本来就不敏感。到期立即销毁——不排空、不刷盘——因为持久状态在任务完成时就已经处理完。同一任务后来的调用会初始化一个新容器；镜像与依赖已经在节点上，代价还是那 0.2 s。
7. **资源契约是持久数据跨越边界的唯一通道，它存在的理由是凭证进不了容器。** 一个资源是 `{ name, type, source, ref?, mode }`。`name` 定路径（`/work/resources/<name>`）；`type` 指的是**传输方式**而不是内容类别（`git`、`object`、`prefix`、`url`、`snapshot`——训练好的模型是一个 `object`，数据集通常是一个 `prefix`）；`mode` 是 `ro` 或 `rw`。两个动词：`ensure` 幂等（已在就 no-op，不在就取），因此它同时是「任务中途发现需要新资源」的答案——代价是多出一个目录，不是重启；`sync` 在任务完成时上传那些声明过输出的 `rw` 资源。上传一个 `ro` 资源是错误，不是 no-op。

   传输方式按「数据多久变一次」分，因为一次更新的成本决定了存储的形状。稳定的产物走 `object`/`prefix`——一次写入、一个版本、结束。频繁变化的状态走 `snapshot`：一个 restic 格式的仓库（rustic 读写它，append-only，内容定义分块加去重），`sync` 把路径备份成一个**新的快照**，`ensure` 恢复其中一个，就地恢复、只碰有差异的文件。这是「完成时上传」对一个每个任务都在变的工作树付得起的原因，也正是快照仓库不是被否决的「整机文件系统捕获」的原因：它的范围是一条声明过的路径，第二份快照只花变化掉的那部分。

   **任何写入都不需要审批，理由在机制里而不在乐观里。** 每一种传输都分配一个新版本而不是覆盖旧的：git 在分支上写一个 commit，对象存储保留对象版本，快照仓库是 append-only。指向当前版本的那个**引用**是控制面的记录，不是节点自己挑的，所以一次坏写入的撤销方式是「不推进指针」——之前的状态从未被销毁。因此 `sync` 要返回它产出的引用（分支与 commit、对象版本、快照 id 与标签），让结果同时携带审计轨迹和撤销句柄。一个必须事先判断才安全的写入需要人；一个分配版本的写入只需要一个指针。
8. **节点不持有任何长期凭证。它申请、自己花掉，而且数据面不经过控制面。** 材料——presigned 对象 URL、短期 VCS token——由控制面在任务申请资源时铸造，沿连接下发，由节点直接对着存储用掉：不中转，因为中转会让控制面变成每一份产物的带宽。它只活在节点内存里，存活期恰好一次 `ensure` 或一次 `sync` 那么长：不落盘、不进环境变量、不交给摊位。通常情况下它的暴露窗口是空的——`ensure` 在脚本启动之前跑，`sync` 在脚本退出之后跑；任务中途发现资源是例外，那里的保证是结构性的而不是声明性的：摊位以另一个 uid 运行，所以节点进程里的凭证对下发的代码不可读。模型永远看不见凭证：它按名字申请资源，拿到的是一个路径。
9. **工作区不是独立概念。** 它就是一个 `git` 类型的资源（比如叫 `repo`），`cwd` 指向它内部。一个环境是 `image + network + task`；盘上的一切都是资源。`fs_scope`、`deny_read`、作为策略的 `cwd` 在容器类里没有意义——路径是我们建的，里面没有别的东西——它们只作为 `Host` 类的粗粒度授权存活。
10. **节点就是容器的根进程，于是「容器控制」这件事不再存在。** `docker run --rm --init <image> effector --control-plane <url> --token <…>`——节点是 PID 1，下发的脚本是它的子进程，它退出容器就退出。这样执行端里整套容器控制面直接删除：没有 create/attach/exec/destroy，没有崩溃后的孤儿容器，也不需要单独的收尸者，因为容器的寿命**就是**进程的寿命。特权从执行端挪到**启动器**——集群里是一个 `Job`，单机上是一个最小 spawner（或者干脆是控制面自己，或者一个 systemd 模板单元）——于是「跑不受信任代码的组件」不再是「能创建容器的组件」。
11. **连接时一个 token；授权就是这条连接。** 节点在连上的那一刻认证一次，之后每一次下发都骑这条连接，本身不再携带任何凭证。两个后果，都是简化：授权不可能从别处来，所以没有「每次调用检查一次」这种要写、也会漏的东西；吊销也不需要机制——关掉连接就是吊销。注册帧不再是身份证明（ed25519 签名、nonce 挑战、`read_signing_key`、`private_key_path`），而是形状声明：别名、能承载哪几类、能跑哪些镜像。节点的寿命于是是一条规则两个输入——连接结束就退出，空闲宽限到期也退出，谁先到算谁——所以宽限计时器不是池里的一张表，而是进程自己的超时。token 一直有效直到被替换：它是机器的钥匙，统一的过期日期只会在一个没人选定的日子制造一次事故。吊销就是重新铸造——注册表存的是 token 的**摘要**，从不存 token 本身，所以新的凭证让旧的在下一次拨号时不再匹配——并且同一时刻只允许一条活连接（第二次连接顶掉第一次），于是泄露的 token 扩散不出第二个节点，它的暴露窗口是一条连接而不是一辈子。
12. **审批是有的，它属于 skill 的某个步骤，永远不属于某个系统调用。** 环境决定可能造成多大破坏；剩下的那些只有人才能做的决定——部署这个、花这笔钱、动那套系统——只有落在一个**人能读完的单位**上才有意义。那个单位就是 k10r 里存的 skill（前置条件、步骤、经验、后置验证），决策点是其中的某一步，控制面可以在那一步把一张**表单**送到读者面前：选项、参数、随后会发生的验证。表单问的是模型不可能知道的东西；它不是问「能不能跑 rm」。这也是为什么粒度是步骤而不是调用：逐调用弹窗会被条件反射地点掉，步骤级表单才会被读。Effector 不参与其中：它没有审批面，也不该长出一个，因为节点看见的是调用，不是 skill——而一个能暂停 turn 的部件属于 gravity，turn 控制本来就在它那里。
13. **Docker 提供不了的部分，Effector 留着。** 节点拥有：控制面连接、代码下发、induction 帧协议（带类型的 invoke/iterate 流，不是一个字节管道）、逐调用的计数、取消语义、环境登记表、自己的空闲租约、资源供给。Docker 提供的是隔离、上限、镜像、一个 kill 句柄和管道——这些没有一样是帧、下发或记账。简化是真实的，但它是概念层面的，清单见下。

## Considered and rejected

- **保留 jail 作为默认，把容器当选项。** 那等于要同时维护两套容纳叙事，而其中被骗过的那一套，正是 2026-11-09 要为它打补丁才够得着代理的那个。一个边界，显式选定。
- **按环境规格复用容器。** 最便宜的缓存，代价是静默合并任务——包括跨用户。否决理由与「共享的记忆面必须按用户划分命名空间」是同一条。
- **关闭时把容器文件系统快照到对象存储。** 整机捕获很大，而且每次关闭都要上传，会把设计里便宜的那一半变成慢的那一半。`snapshot` 这个传输是干另一件事的：一条**声明过的**路径，追加进一个去重仓库，所以第二次捕获只花变化掉的部分。持久化依然是决定出来的（文本走 git、产物与状态走声明过的 `rw` 资源）；没声明的东西就是可弃的，这正是要点。
- **把审批降到系统调用或单次写入这一层。** 它保护不了任何东西，而且会把注意力花光：真正需要人判断的是「这一步该不该做、用什么参数做」，那属于 skill 的一个步骤（k10r），配上给 UI 的表单；环境能兜住的东西则不需要任何审批。把两者混在一层，等于用弹窗替代设计。
- **因为写入有破坏性，就用审批把它挡起来。** 它没有破坏性：每种传输都分配版本（分支、对象版本、append-only 快照），而指向当前版本的指针归控制面所有。这道审批保护不了任何「指针回滚」保护不了的东西，却要把一个人的注意力放进每一个任务的路径里。
- **让模型在容器里自己拼 `git` 与 `s3` 命令。** 不把凭证放进容器就做不到，而凭证不进容器正是这套设计存在的目的。
- **拼 `docker` CLI 来驱动容器。** 一条 CLI 字符串没有 owner：它可以半路失败，会留下残余容器，而资源生命周期需要的是幂等 API。直接使用 Docker Engine API；CLI 只留给人排查。
- **把 Docker socket 交给被沙箱的脚本。** 那等于把宿主交出去。
- **资源材料经控制面中转。** 它能让每个容器都不含凭证，但代价是控制面变成每一份产物（模型、数据集、构建输出）的带宽——这个成本随客户数增长，与控制面真正该干的事无关。铸造材料、由节点直接花掉，既保住了要紧的性质（容器里没有任何长期东西），又不需要中转。
- **给摊位一份长期存储凭证。** 传输是节点侧的动作；摊位的职责是往一个路径里写文件。凭证放在摊位里，等于把权限放在唯一一个跑着没人审查过的代码的地方。

## Consequences

- **节点声明自己能承载哪些类，其余的按名字拒绝。** 没有 Docker 的机器是一个「进程内 + 宿主」节点；它不会默默接受一个 turn 刚写的脚本并在没有任何边界的情况下运行。这条拒绝复用 mount 已有的形状（「这里没有能承载这一类的环境——本节点声明：进程内、宿主」），于是部署真正具备的能力是被陈述出来的，不是被假设的。
- **特权组件是启动器，节点什么都不长期持有。** 创建容器的一方持有 Docker socket（≈ 机器上的 root）——集群里是一个 `Job`，单机上是一个小 spawner。跑不受信任代码的节点不持 socket、不持身份私钥、不持存储凭证：连接时一个 token（注册表只留它的摘要），以及每次传输现领、用完即失、只存在内存里的材料。原来那条立场（「执行不受信任代码的容器不持有数据面凭证」）没变，只是从靠纪律守变成靠形状守。
- **节点成为资源管理器，控制面成为指针的保管者。** 每个资源一对 `ensure`/`sync`：每个任务都在变的状态用一个 `snapshot` 仓库，不变的东西用 `object`/`prefix`，文本用 `git`。节点搬字节并报告它产出的引用；控制面记录哪个引用是当前的——这才是「回滚是指针移动而不是恢复」的由来。这项职能在旧架构里缺失，不是有意省略。
- **注册握手缩小，执行端多了一项本来就该有的职能。** ed25519 注册签名、nonce 挑战、`private_key_path` 随本记录退役：身份由连接时的 token 确证，紧随其后的帧只描述节点。取而代之的是一个资源管理器——`ensure`/`sync` 加铸造出来的材料——旧架构从未规定它，因为旧架构从未决定持久数据在哪里跨越边界。
- **路由不再是一个问题。** 今天一次调用必须落到「某个服务这种语言的已注册节点」上，那其实是伪装成匹配的调度。一个任务一个容器之后，谁创建容器谁就已经决定了任务在哪跑；控制面从调度退回分发。
- **PID 1 是职责，不是形式。** 节点收自己的子进程、处理 `SIGTERM` 并转发给摊位；`--init`（tini）负责节点不必关心的部分。
- **镜像成为部署件。** 它的构建、分发、离线可用性，取代今天的 runner 脚本，成为客户现场会出问题的那一环。按语言分的漂移表（每（别名 × 语言）一个 mount）塌缩成「镜像就是 mount」，这既是简化，也是政策变化：节点不再声明自己服务哪些语言，它声明自己能拉起并运行一个镜像。
- **帧协议留下，而且不是惰性。** 容器给的是一条字节管道；它给不了带类型的 invoke、流式迭代、在边界处取消、逐行记账。删掉协议，等于把这些全部挪进 shell 脚本和命令行上的 JSON。
- **同一任务的调用共用一个容器，任务之间不共用。** 中间文件在任务内留存、随任务消失。可见的代价是任务之间不能继承彼此下载的东西；不可见的好处是，制造一团乱不需要任何人批准。
- **成本是量出来的，不是假设的：** 每个容器约 0.2 s，常见情形下每个任务只付一次（宽限期吸收了同一轮后来的调用）。
- **有意不在这里裁决的：** 镜像在哪里声明（任务、skill，还是节点默认）；镜像拉不下来时节点怎么办；`sync` 失败是否让任务失败（它必须可见，本记录不在「任务失败」与「任务成功但产物错误很响」之间选择）；两个任务声明同一个 `rw` 资源名时的写锁规则（名字是逻辑资源的身份，当前的意图是同一时刻一个写者）；以及每个后端上摊位的 uid 如何保证——「凭证只在内存里」这条依赖它，而今天它是部署假设，不是节点会检查的东西。
