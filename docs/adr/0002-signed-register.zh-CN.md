# 0002 — 握手是签名，不是共享密钥

> **Languages:** [English](0002-signed-register.md) (primary) · [中文](0002-signed-register.zh-CN.md)

**Status:** Accepted (2026-10-29)。已落地：`Frame::Challenge` / 带签名的 `Frame::Register` /
`Frame::Refused`、`effector keygen`、`effector register`、`private_key_path`。
**Date:** 2026-10-29

## Context

注册原本用的是共享凭据：节点从环境变量里读一个 token，放进 `Register` 帧，控制面拿它和自己
持有的值比较。同一个值、两端各有一份、不证明任何事。

这种形状在三点上站不住，第三点才是要紧的：

1. **凭据可复制，所以它指认不了机器。** 任何拿到 token 的人都是这个节点。信任变成了"曾经
   知道那个字符串的人"，而不是"这台机器"。
2. **环境变量里的密钥默认会泄漏。** `/proc/<pid>/environ`、崩溃转储、日志里一句 `env`、子进程
   继承——凡是这个用户跑的东西都能读到，而这个节点本来就该去跑别人的代码。
3. **控制面的信任表没有东西可用来做键。** prism 的节点注册表（`prism ADR-0015 §3`）把别名映射
   到**公钥**，判定 `registered | pending | conflict`。共享 token 在那张表里无处可查——那张表
   本来就是为这条要替换掉的握手建的。

传输层原本就是对的（一条向外的 WS，一条消息一个帧）。缺的是证明，不是管道。

## Decision

控制面先说，给出一个 nonce。节点用留在自己机器上的 ed25519 私钥（`private_key_path`，
`effector keygen` 写成 0600）对它签名。`Register` 携带**公钥**与签名；宿主验签，再拿这个公钥
去自己的注册表里判定信任。

属于决策本身（不是实现余量）的几点：

- **任何信任姿态下都是宿主先说。** `open`（不查注册表）与 `required`（查注册表）是同一条线上
  形状：节点不需要知道自己在被怎么信任，也没有第二种帧形状要跟着同步。
- **两种姿态都验签。** `open` 的意思是"没有注册表"，绝不是"没有证明"。跳过验签的宿主会接受一个
  写着别人公钥的 `Register`。
- **被签名的消息是本 crate 里的一个函数**（`register_message`）：协议写明确切字节并带版本前缀，
  签名侧与验签侧无法漂移成一个没人能调的格式差异。公钥与签名走 base64；nonce 是 16 字节随机数，
  base64。
- **nonce 每连接一份**，所以抓到的 `Register` 无法重放到另一条连接上。验签用 `verify_strict`——
  可锻造的签名或弱公钥一律拒绝，因为注册表里的公钥必须确切指认一个签名者。
- **拒绝要在关掉 socket 之前说出来**（`Frame::Refused { reason }`）。需要这个理由的操作者在
  **节点那台机器**上；否则理由只存在于宿主的日志里。
- **注册是网络事实，服务是运行时状态。** `effector register <config>` 是一次握手、一个判定、
  然后退出。重启会按连接重新赢得信任——不存在"注册过一次"的模式要跟操作者可能改过的注册表同步。
- **密钥是启动事实。** 读不到密钥的节点拒绝运行，跟"能力声明没有执行点"（ADR-0001）同形。不生成
  兜底密钥：启动时凭空生成的密钥，操作者不可能已经登记过。
- **`keygen` 永不覆盖。** `create_new`——密钥文件已存在就是错误，因为静默替换会让旧公钥占着的
  那行注册记录变成孤儿。

## Consequences

- 凭据字段两端都消失（`EffectorConfig::credential_env` → `private_key_path`；
  `Frame::Register.credential` → `public_key` + `signature`）。不再有任何东西从环境变量读密钥。
- prism 的 `required` 姿态终于有东西可判：判定结果门禁连接，`pending`/`conflict` 带理由拒绝，
  审批队列就是注册表本身（`POST /admin/nodes/{alias}/approve`）。
- aura 的本地模式 effector 网关（`serve_effectors`）也发挑战、也验签，但背后没有注册表——本地
  模式没有操作者可供审批，造一个出来就是第二套信任平面。
- 信任仍然跟随所有权：节点被信任，是因为有人为那个别名批准了它的公钥。握手证明这把钥匙，本身
  不授予任何东西。
- 未做：密钥轮换 = 吊销旧公钥、批准新公钥——没有带内的轮换帧，且已登记的公钥绝不会被静默替换
  （那是注册表的规矩，不是传输层的）。
